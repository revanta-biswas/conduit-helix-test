## Story Context

**As** the Solo Developer, **I want** a new `conduit-next/` Next.js 15 App Router package added to
the npm workspaces, **so that** I have a running, empty foundation to build the migration on without
touching `backend/` or `frontend/`.

**REQ-F-01** (requirements.md): "A new `conduit-next/` package MUST be created as an npm workspace
member, running Next.js 15 (App Router), alongside the existing `backend/` and `frontend/` packages
(both left untouched until cutover)."

**Acceptance Criteria** (stories.md):
- AC-1: `conduit-next/` exists as an npm workspace member (root `package.json` `workspaces` includes
  it), running Next.js 15 with the App Router.
- AC-2: `npm run dev -w conduit-next` starts the app without errors on a port that does not collide
  with the existing `3000`/`3001`.
- AC-3: ESLint and Prettier are configured for `conduit-next/`, consistent with the plain-JavaScript
  decision (REQ-NF-06) — no TypeScript config is introduced.
- AC-4: `backend/` and `frontend/` are unmodified by this story (verified by diff).

**Application Design** (application-design.md): Story 1 introduces no business-logic components of
its own — it is the anchor node (`Story 1 (scaffold)`) that Story 2's `lib/db/*` and every later
story's `lib/services/*` / `app/**` depend on. No component-level design to ground beyond the package
scaffold itself.

**Architecture Section 10 constraints applicable to this story**: none of ARCH-01..06 are exercisable
by a pure scaffold with no application code, no data access, no session handling, no logging, and no
Route Handlers accepting a request body — every constraint requires code this story does not write.
All six will be scored `N/A` (excluded, weights renormalised) by J1 for this diff, per
`common/eval-framework.md` Section 4.1 Rule 5. This is stated here as the plan's own self-check, not
asserted at review time.

**Design References**: none registered — no UI prototype/spec applies to a package scaffold.

## Plan Steps

- [x] **Step 1 — Project Structure Setup: scaffold `conduit-next/` (REQ-F-01, AC-1)**
  Create a new Next.js 15 App Router project at `conduit-next/`, plain JavaScript (no TypeScript,
  REQ-NF-06), using the App Router (`app/` directory), matching the minimal structure Next.js's own
  `create-next-app` produces for a JS + App Router + no-Tailwind + no-`src/`-dir project: `app/layout.js`,
  `app/page.js`, `next.config.js`, `jsconfig.json`, `public/`, `.gitignore`, `package.json`.

- [x] **Step 2 — Workspace wiring + dev port (REQ-F-01, AC-1, AC-2)**
  Add `"conduit-next"` to the root `package.json` `workspaces` array. Set `conduit-next/package.json`'s
  `dev` script to run on port `3002` (frontend already owns 3000 via Vite default, backend owns 3001 per
  `.env.example`/existing convention) — `next dev -p 3002`. Also set `build`/`start`/`lint` scripts
  consistent with a standard Next.js scaffold.

- [x] **Step 3 — ESLint + Prettier configuration (REQ-F-01, AC-3)**
  `conduit-next/eslint.config.mjs` (flat config, generated by `create-next-app` itself — `.mjs`
  extension, not `.js`, since `conduit-next/package.json` has no `"type": "module"` and a flat ESLint
  config needs ESM `import`/`export default`; this is a plan revision from the originally-written
  `.js` — kept AS-IS rather than renamed, consistent with `backend/eslint.config.js` /
  `frontend/eslint.config.js`'s flat-config convention already in this repo) extending
  `next/core-web-vitals` in JS mode (no `next/typescript`). Added `.prettierrc.json` plus
  `format`/`format:check` scripts. No `tsconfig.json` is introduced anywhere in `conduit-next/`.

- [x] **Step 4 — Verify the dev server actually starts (REQ-F-01, AC-2)**
  Run `npm install` at the workspace root (resolves the new `conduit-next` workspace member and its
  Next.js dependency tree), then start `npm run dev -w conduit-next` in the background, poll it for a
  successful HTTP response on port 3002, then stop it. This is the actual proof for AC-2 — not an
  inference from the config.

- [x] **Step 5 — Verify `backend/` and `frontend/` are untouched (REQ-F-01, AC-4)**
  Run `git diff --stat` against the epic branch before committing and confirm the only paths that
  changed are `conduit-next/**`, the root `package.json`/`package-lock.json`, and this story's own
  spec/tests/reports artifacts. Any other path is a plan violation and must be reverted before commit.

- [x] **Step 6 — Unit Test & Coverage (MANDATORY, same run)**
  A pure scaffold has minimal custom logic. Add one basic smoke test
  (`conduit-next/__tests__/app.test.js` via a lightweight JS test runner, or a rendering smoke test of
  `app/page.js`) so there is something concrete to measure, generate it, run it, and measure coverage
  on `conduit-next/`'s own new/changed code. Iterate to `unitTestCoverageMin` (90%) or document a
  narrow, honest exception per code-generation.md's coverage-tooling waiver rule if the stack genuinely
  cannot instrument a static-export scaffold page beyond what the smoke test already covers.
